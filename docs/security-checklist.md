# Launch Security Checklist

- [x] Apply the least-privilege public API grants migration; retain RLS policies as the row-level boundary.
- [ ] Verify `user_roles` contains only the approved owner UUID. Public signup is disabled; no role is assignable in the browser.
- [ ] Confirm an unverified account and a verified non-owner receive no owner data or owner-function access.
- [x] Remove direct `anon` and `authenticated` table grants from customer applications, remarks, documents, audit events and notification logs.
- [ ] Confirm customer records are linked to a verified user ID only when the submitted email matches that account.
- [ ] Confirm tracking returns a generic mismatch error, rate-limits attempts and never puts personal data in a URL or cache.
- [ ] Confirm all public application submission has explicit consent and server-side validation.
- [x] Confirm the customer application form has no customer file-upload control. The owner-only document upload remains available for approved customer documents.
- [ ] Confirm `application-documents` is private, file limits/types are enforced in the owner UI and storage policy, and signed URLs expire quickly.
- [ ] Set `TRACK_RATE_SECRET` and email provider secrets in Supabase only; rotate any credential accidentally exposed.
- [ ] Confirm email logs and UI distinguish sent, failed and not-configured outcomes for applications, grievances and insurance requests.
- [ ] Set exact trusted CORS origins for production and remove preview origins from production if not needed.
- [ ] Verify the hosted Supabase Auth settings match the repository's link-only email templates and password-recovery redirect allowlist. TOTP and code-based email templates are disabled by business request.
- [ ] Enable leaked-password protection if available in the hosted Auth settings; use strong unique passwords because MFA is intentionally disabled.
- [ ] Keep customer database backups and define retention/deletion procedures appropriate to the business.
- [ ] Review privacy policy/terms with the business and relevant legal advisor before collecting real customer data.
- [ ] Verify custom-domain HTTPS, redirects, robots/sitemap and preserve all business email DNS records.
- [ ] Run desktop/mobile tests for every route, service search/import, featured flags, non-owner rejection, document permissions, payment verification and email paths in a non-production project.
- [ ] Do not mark bank SMS as automatic proof of payment. An official signed bank/payment-provider webhook or independently verifiable bank feed is required before unattended payment confirmation.
